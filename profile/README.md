# profile/

How the owner wants their resumes and letters made. The ledger
(`ledger/ledger.yaml`) says what is true; this folder says what to show and how
it should sound. Nothing here is a fact: a preference never adds a claim.

| File | Written by | Read by | Holds |
|---|---|---|---|
| `preferences.md` | `/onboard` (onboard-owner skill) Phase 4; updated whenever the owner states a new preference | every skill | workflow, targets, positioning themes, contact items and section order, what never to list, wording rules, where finished PDFs go, whether to write cover letters |
| `voice.md` | `/onboard` Phase 5 (only with cover letters) | cover-letter skill | how the owner writes, each trait backed by a quote from their samples |
| `samples/` | `/onboard` Phase 5 | voice derivation and the cover-letter voice review | the owner's own writing, text only, one file per piece |
| `*.example.md` | the template | `/onboard` | the shape of the two files above, with placeholder slots |

The repo is not set up until `preferences.md` exists. Run `/onboard`.

Edit either file by hand any time; the next session reads the new version.
Redo a whole file with `/onboard preferences` or `/onboard voice`.

These files are personal. They belong only in a private repository.
